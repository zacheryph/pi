00 · North star

Manage the migration.
Not an endless agent.

A campaign is a durable, editable plan whose steps advance only when evidence, scripted checks, and human gates say they can. Pi is your management console; subagents work on bounded implementation tasks.

LOCAL ONLYYAML FIRSTSCRIPTED RECONCILESCHEDULED WHILE PI RUNSHUMAN AUTHORITY

LLM does meaningful work

Interview, investigate, plan, write modules and scripts, prepare draft PRs, interpret unexpected failures, revise a campaign.

Code does routine work

Schedule checks, collect check outputs, correlate IDs, evaluate the graph, enforce gates, notify and journal every transition.

Operator keeps control

Change strategy, stop checks, approve the plan, mark PR ready, authorize merges and halt a wave independently of the model.

02 · Plan creation

Interview first. Commit to evidence.

1 / Scope & destination

Goal, current state, impacted repositories/stacks, AWS/network boundaries, owners, maintenance windows and rollback expectations.

2 / Decompose

Discovery, prerequisite module changes, multiple PRs per stack, canaries, waves, cleanup, explicit hard and soft dependencies.

3 / Choose checks

How does Pi know comments are resolved, review is approved, Spacelift applied, connectivity recovered? Generate candidate scripts, then review.

4 / Approve execution policy

Review-round cap, draft→ready responsibility, auto-merge setting, production gates, notification target and reconcile frequency.

Interview output: Paused YAML draft, DAG view, first eligible work, risks, open unknowns, a testable gate specification, and next decision. Unknown IDs become runtime facts filled by checks or short agent tasks—not fake values.

→
Platform scriptsGitHub, Spacelift, etc.

Runtime

Single Pi process schedules due checks. Timer is transport, not the source of truth. Restart re-evaluates due checks from persisted timestamps.

Storage

Plan and operational state as separate YAML files; atomic replacement. Add SQLite or an append-only journal if multi-process coordination or larger histories demand it.

Portability

Every check uses a user-supplied argv/script. Platforms can be heterogeneous; adapters supply convenient templates only, never a closed platform registry.

Multi-step, revisable, human-gated.

→
Spacelift applyscript polls exact run
→
Validate & advancescript and wave gate

Comment handling invokes an agent only when there is actionable review feedback. Ordinary CI status polling and waiting for teammates remains code-only. After N review cycles or ambiguity, block and ask the operator. Merge must re-check head SHA and approvals immediately before execution; the setting is not an override of branch protection.

05 · Data contract

Intention ≠ observation.

campaign.yaml / desired workflow

id: routing-migration
title: Regional route migration
goal: Routes migrated, connectivity healthy
settings:
  reconcile_minutes: 15
  allow_commands: true
  auto_merge: false
  max_review_rounds: 3
steps:
  - id: draft-canary
    title: Prepare canary PR
    work: { kind: agent }
    gates:
      - id: user-ready
        kind: human
  - id: canary-apply
    title: Validate Spacelift apply
    depends_on: [draft-canary]
    work: { kind: none }
    gates:
      - id: applied
        kind: command
        command: [node, scripts/check-apply.mjs]

state.yaml / observed truth

revision: 8
paused: false
steps:
  draft-canary:
    status: done
    work_complete: true
    facts:
      pr_number: 431
      head_sha: abc123
    gates:
      user-ready:
        status: passed
        at: 2026-10-15T12:00:00Z
  canary-apply:
    status: waiting
    work_complete: true
    facts:
      stack: core-network
    gates: {}
history:
  - kind: work_recorded
    step: draft-canary
    detail: "pr_number, head_sha"

Step IDs are stable. Revision changes are validated and audited. Previously verified outcomes are not silently deleted. Future revisions should explicitly invalidate affected descendants when a passed prerequisite changes, with human review before proceeding.

06 · Gates / schedule

A check is a program, not a prompt.

PASS · exit 0

Valid evidence recorded. Advance only when all required gates have passed. Script may emit JSON evidence.

WAIT · exit 3

Still pending. Persist observation. Check again on configured schedule; no model invocation.

BLOCK · any other exit

Unexpected error, unsafe change or missing authorization. Pause the affected path, raise a human question, and require remediation.

# Script environment:
PI_CAMPAIGN_ID=routing-migration
PI_CAMPAIGN_STEP_ID=canary-apply
PI_CAMPAIGN_GATE_ID=applied
PI_CAMPAIGN_FACTS_JSON='{"pr_number":431,"stack":"core-network"}'

# Structured response on stdout:
{"status":"waiting","detail":"run 9984 pending","evidence":{"run_id":"9984"}}
# Exit code 3 keeps this gate waiting.

Run commands directly (no implicit shell), set timeouts and concurrency caps, bound output, and never parse a vague success text as an approved apply. Agent may discover missing IDs once and update durable facts before the next script check.

07 · Recovery and controls

Pause is not cancellation. Cancel is not rollback.

ActionEffectOn resume
Pause campaignNo new actions; cancel local active checksRebuild eligible steps from YAML
Cancel one workerStops bounded Pi task; preserves artifactsInspect branch before retry
Block gateRecord evidence/question; downstream waitsOperator corrects input or revises gate
Revise campaignValidate DAG; retain prior evidenceEvaluate changed dependencies
External action already startedNot automatically undoneReconcile observed state; don't duplicate mutation

Completed actions must be correlated to their external identity: repository, PR number, commit SHA, Spacelift stack and run. Eventual consistency means a merged PR is not proof of a successful apply. Restart reconciliation is mandatory.

09 · Notifications

State transitions, not spam.

Pi

Above-editor summary, warnings and review-request inbox in main management session. Show what changed and which gate needs attention.

Slack adapter

Optional outbound notification, configured via environment-based secret reference, only on state changes and stale-gate escalation. Never a webhook receiver.

Dedup

Notify once per campaign / step / gate / state revision. Acknowledge, snooze and escalation settings can be layered later.

11 · Delivery plan

First reliable check. Then autonomy.

Implemented in MVP

YAML + checks + Pi UI

Plan schema and validation, persisted state, paused default, per-gate command reconciliation, human approval command, interview scaffold, compact widget, tests.

Next

Draft PR lifecycle

Bounded worker dispatch, review comment handling cap, ready/approved gates, policy-gated merge, fact collection, Spacelift script templates.

Later

Hardening + UX

Interactive DAG browser, complete interview, process locks, robust crash recovery, notification adapters, explicit reopen and invalidation semantics.

Important: This is an engineering target plus a tested foundation. The initial implementation does not yet create PRs, merge PRs, invoke workers automatically, send Slack messages, or offer a fully interactive graph browser. The settings document these extension points without claiming they work.
